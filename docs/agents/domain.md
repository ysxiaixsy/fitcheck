# Domain docs

This repo uses a single-context layout:
- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

## Before exploring

Read the glossary and any ADRs relevant to the work.
If they do not exist, proceed silently. Domain-modeling creates
them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the wording or note
the gap for domain-modeling.

## Decisions

Explicitly surface any conflict with an existing ADR, including
the ADR identifier and the reason to revisit it.
